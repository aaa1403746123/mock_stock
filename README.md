# MarketLab · 模拟交易实验室

Vue **3.5.44**（创建时 npm 最新稳定版）+ TypeScript + Vite 8。独立 Node.js 撮合服务、WebSocket 行情和 SQLite 持久化。仅使用虚拟股票及虚拟资金。

## 本地启动

需要 Node.js **22.13 或更新版本**。当前电脑默认 Node 14 不支持本项目；项目提供的启动脚本会为当前进程选择已安装的新版本，不修改系统默认版本。

```powershell
.\start.ps1
```

访问 http://localhost:5173 。首次打开会创建访客管理员，市场包含 50 只虚拟股票、1000 个常规机器人和另外 15 位游资，共 1015 个机器人。建议在右上角「保存账户」设置用户名与密码。用另一个浏览器或隐私窗口访问，可创建资产独立的另一个账号；也可以在右上角创建新账户。

标准启动命令（先切换到支持的 Node）：

```sh
npm install
npm run dev
```

生产构建及本地运行：

```sh
npm run build
npm start
```

生产构建访问 http://127.0.0.1:3001 。服务默认仅绑定本机；开发网页通过代理连接后端，所有浏览器共享同一后端市场。不是外网部署配置。

## 已实现

- 交易大厅：50 只股票切换，各自独立的实时价格、分时、1/5/15 分钟 K 线、日 K、月 K、年 K、五档盘口和匿名逐笔成交。仅同一股票的买卖委托可以撮合。
- 图表指标：蜡烛实体显示开收盘价，上下影线显示实际最高/最低价；独立成交量区域与价格图同步缩放，红涨绿跌，可通过「量柱」开关显示。MA5/10/20/30/60 按当前周期的收盘价计算，点击图例可单独开关；悬停显示对应的日期、开高低收、成交量和均线数值。未积累足够周期时均线显示「—」。
- 成交标记：图中红色 B 向上箭头表示本人买入成交，绿色 S 向下箭头表示本人卖出成交，分别位于对应蜡烛下方和上方。依据当前账号最近 200 笔成交，只标记当前股票及图表时间范围内的成交；切换分时、分钟、日、月、年周期时自动对齐，同一周期同方向合并为一个标记，买卖同时存在时同时显示 B、S。
- 交易：限价与带 ±2% 价格保护的市价委托、价格优先/时间优先、部分成交、撤单、资金与持仓冻结、同账号防自成交、请求去重。
- 独立账号：每人初始 100,000 元、访客转注册、密码哈希、会话鉴权。每个账号的五十只股票共用自己的现金，持仓、可卖数量、成本和盈亏按股票分别核算；普通账号只能查看自己的私有交易与资产。
- 常规机器人：默认 1000 个，分为随机散户、趋势散户、价值投资者、资金大户、流动性提供者，分布于五十只股票。有限资金与持仓，独立决策状态，只依据公共行情与自身资产下单。机器人使用同一撮合流程，不直接设置价格。
- 游资：额外 15 个独立账号，每人初始现金 2 亿至 30 亿元，无初始持仓。突破追涨、强势接力、回调低吸、放量反转、趋势波段各 3 人，观察窗口、出手频率和风险阈值各不相同。只根据已发生的公开量价、匿名五档深度及自身资金持仓判断，在五十只股票中择强交易，没有合适信号时观望。监控页筛选「游资」，可查看姓名、风格、资产盈亏、下单和成交依据。

游资 01–15 的资金档位依次为 2、4、6……30 亿元。已有游资通过一次性补充现金升档，初始资产历史、持仓和委托保留，新增资金记录在「资金调整」中并从交易盈亏中剔除；当前总资产仍随持仓行情和交易变化。重启不会重复注资，新一轮直接按新档位初始化。
- 管理员资产调整：交易页「账户总资产」旁点击「调整」，填写自己的目标总资产及原因；资金增减单独记账，并可查看调整记录。
- 模式：自由练习 T+0 / 普通 A 股主板规则 T+1，全市场统一；管理员通过新建练习切换，历史轮次归档保留。
- 时间：1/5/20/60 倍速、暂停、跳转下一模拟交易日。无在线 WebSocket 客户端时模拟时钟停止。
- 复盘：分钟级资产曲线、累计收益、最大回撤、成交 CSV 导出、历史轮次切换。
- 持久化：SQLite 保存市场、账号、订单、会话与历史轮次，服务重启可恢复。
- 管理员账户监控：侧栏「监控」查看所有真人及机器人账户的现金、可用/冻结资金、分股票持仓、已实现/浮动盈亏、收益率；按类型筛选和盈亏排序，导出账户报表，账户列表每页 50 个。每个账号可查看下单、逐笔成交、撤单原因及操作后的现金/持仓/已实现盈亏，以及资金调整记录，也支持历史轮次。

## 规则口径

金额按整数「分」、股票按整数「股」存储。每次成交按股数计量一次；行情由成交生成，未成交挂单与撤单只影响盘口。没有成交的交易分钟记录平价、零量 K 线。

为让页面初次打开即有可观察的行情，市场初始化时会先运行机器人 90 个模拟分钟；这些历史 K 线也来自撮合成交。

日 K 按北京时间零点分日并持续保存，月 K、年 K 按自然月、自然年汇总日 K，最高价取实际最高成交价、最低价取实际最低成交价、成交量求和。未结束的周期会实时更新；有成交的周期以第一笔实际成交作为开盘价，无成交占位不会改变实际开高低收。未模拟过的月份、年份不会补造行情，因此新一轮初期可能只有一根月 K 或年 K。

升级时会从仍保留的分钟行情回填日 K。此前已清理的行情无法恢复，最早回填的日期可能不是完整交易日；从升级后开始，日 K 独立保存，不随分钟数据清理，重启后继续累积。

自由练习允许全天交易、T+0、1 股起买，默认免费。A 股模式首版针对**普通主板连续竞价**，买入以 100 股为单位，卖出零股须一次卖完全部可卖数量；按前收盘价 ±10% 限制申报；工作日 09:30–11:30、13:00–15:00 交易，收盘撤销当日未成交委托，次日可卖此前买入股票。

模拟交易日跳过周末，**暂不含法定节假日、集合竞价、ST、新股、科创板/创业板及真实交易所完整市价申报规则**。当前市价委托统一采用保护价格内立即成交、剩余撤销的练习规则。

可配置费用模板：佣金 0.03%（每张委托最低 5 元）、双向过户费 0.001%、卖出印花税 0.05%；按委托累计成交额计算、部分成交不重复收取最低佣金。该模板用于练习，不声明为实时官方费率。

管理员调整总资产通过增减现金实现，不改变持仓和挂单。目标金额必须覆盖提交时的全部持仓市值与冻结资金，上限为 100 亿元。净资金调整为累计现金注资与股票配置价值之和减去提款；累计盈亏 = 当前总资产 − 初始总资产 − 净资金调整。收益率 = 累计盈亏 ÷（初始总资产 + 累计现金及股票投入），提款不减少该分母。盈亏趋势及复盘曲线剔除净资金调整，注资不会产生交易盈利。

游资采用分批限价委托，单票目标仓位上限为总资产的 16%–24%，总目标仓位上限为 50%–70%，每笔买入预算为总资产的 2%–4%，并受近期成交量参与比例、可用资金与未成交挂单预留约束。价格上涨本身可能使持仓占比被动超过目标上限，此时不会继续加仓。止损阈值为 2%–4%，止盈阈值为 4.5%–9.5%，盈利后的高点回撤触发减仓；具体成交仍受对手盘、涨跌幅及 T+1 限制。资金有限、不使用未来行情，策略可能亏损。

每个模拟时钟步最多处理 200 个到期机器人的决策，1015 个账号共同轮转分批执行。加速时仍受该上限约束，到期但未执行的机器人在后续时钟步依次处理。

图表保留每只股票最近 1,440 个交易分钟及本轮已记录的日 K，月 K/年 K 从日 K 汇总；账户资产曲线保留最近 1,440 个采样点。页面显示最近 200 条个人委托与成交，CSV 导出当前显示的最近 200 笔。历史轮次列表显示最近 20 轮。撮合快照保留全部有效挂单及真人订单；机器人已结束订单保留最近两个模拟小时内的最新 2000 条。成交超过 10000 条时，保留最近 5000 条及全部涉及真人的成交。管理员操作流水单独保存在 SQLite 的 account_operations 表中，不随快照清理；每页 50 条，按游标加载更早记录，历史轮次可查看最近 100 轮。

## 数据与检查

管理员访客会话丢失时，可以在项目目录用本地维护命令给自己的现有账户补充管理员权限，例如 `npm run admin:grant -- "练习者 08"`，也支持完整账户编号。仅持有本地数据库文件权限的维护者可以执行；没有网页提权接口。服务会自动应用授权并保留账户资产、订单与登录状态，未运行时在下次启动应用。随后在右上角保存账户，设置用户名密码，避免再次丢失访客会话。

数据库在 `data/market.sqlite`，由 SQLite WAL 确保快照与归档的原子保存。此目录已忽略版本控制。请在备份时停止服务，或使用 SQLite 支持的在线备份方式。

```sh
npm test
npm run build
```

测试覆盖价格/时间优先、资金股数守恒、部分成交、费用、冻结释放、T+1、价格限制、交易时段、收盘撤单、幂等请求、防自成交、跨股票撮合隔离与共用资金冻结、管理员资金调整和盈亏口径、1015 个机器人轮转与可重复运行、游资策略信号/仓位/退出纪律、接口权限、WebSocket 隔离、旧数据迁移、归档和服务重启恢复。

源码：`src/` 为 Vue 界面，`server/engine.ts` 为撮合与模拟引擎，`server/index.ts` 为服务及持久化，`src/shared/types.ts` 为共享模型。

本地试用版使用单进程撮合。对公网开放前需另行配置 HTTPS、账户恢复、运维监控与容量策略。

图表使用 [TradingView Lightweight Charts™](https://www.tradingview.com/lightweight-charts/)，按其 Apache-2.0 许可及归属要求使用。

## 本次升级说明

默认常规机器人数量为 1000，新建练习可设置 8–1000 个，并额外配置 15 位游资；股票总数固定为 50。旧数据库的常规机器人补足迁移只执行一次，后续手动选择较少常规机器人不会被覆盖。此次游资迁移只为当前市场补入 15 位游资，保留原账户资产、委托、登录状态、权限和模拟时间，重启不会重复添加。补入游资使用独立现金资金，通过真实模拟撮合买入持仓。原有单股票数据归入「星海科技」，新增股票使用独立盘口与行情；旧轮次仍可查看。

本机本次升级前已通过 SQLite 在线备份将原数据库保存至 `data/backups/`。新建练习会归档当前轮次，再重置各账号本轮的资产及资金调整记录。

监控 API 仅允许管理员访问，普通账号的 REST 与 WebSocket 行情仍仅包含自己的私有数据，机器人策略不使用监控数据。流水与市场快照在同一 SQLite 事务提交。升级前已存在的数据会回填委托快照和可用成交；无法恢复的历史余额/单笔费用显示为缺失，之前已被清理的机器人记录不能补回。升级后所有被接受的委托、成交和撤单持续记录（不含被拒绝的无效下单、登录和读取操作）。

## 五十只股票与个人底仓

市场现有 50 只虚拟主板股票，保留原十只并增加 600011.SH–600050.SH。股票列表支持按名称、代码和行业筛选，每页 10 只。新增标的各有独立盘口和行情，机器人分散参与；旧市场为新标的配置机器人初始持仓时，以配置市价记录成本及资产投入，不生成虚假成交或盈利。

通过本地维护命令 `npm run portfolio:seed -- "账户名称或编号" 200000` 可为指定真人账户配置底仓：每只不足 20 万股的补足，原有较高仓位保留；不扣现金，新增股票按配置市价计入持仓成本和资产投入。配置不改变行情和成交量，也不添加 B/S 成交标记。「监控 → 底仓配置」保留逐只配置记录。新增底仓作为历史持仓可直接卖出；原有当天买入股票仍受 T+1 约束。

底仓只在配置时补足，卖出后或重启服务不会自动补回；新建练习时，仅已配置该规则的账号重新获得每只股票的底仓。配置请求和市场快照在同一事务保存，失败会回滚，不修改其他真人账户。
